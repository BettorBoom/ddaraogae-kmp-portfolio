# ADR-010 · 10월 11일 지원용 로컬 KMP 시연 범위

- 결정일: 2026-10-09
- 결정자: 사용자(제출 범위와 마감), Codex(위임된 세부 설계)
- 상태: 제출 범위 확정. M04/M06 및 원래 100점 로드맵은 미종료.

## 이유와 선택

지원 마감이 2026-10-11이다. 남은 시간에 전체 M04 실제 배포, M06 인증, 양 플랫폼 상시 위치/지도/동기화까지 검증했다고 주장할 수 없다. 사용자는 웹 제작을 제외하고 앱 자체의 초기 설정과 양 플랫폼 구현을 빠짐없이 보여 주는 **축소된 시연 범위**를 선택했다. 기존 M04 전체 완료 후 M06 착수 규칙을 뒤집거나 완료 점수를 재정의하지 않는다.

이번 제출물은 로컬 `local-preview` 한 기기 사용자, 반려견 이름 하나와 산책 시작·일시 중단/재개·종료·목록/상세·Room 재실행 보존을 Android/iOS 공통 모델·DB·화면으로 만든다. Android는 앱이 화면에 있는 동안 공식 `LocationManager`의 실제 좌표를 받아 정확도/속도/시간 순서와 세그먼트를 확인한 뒤 저장한다. iOS 제품 모드는 실제 GPS가 없는 시간·기록 흐름이다. iOS의 경로 도식 검증용 좌표는 **별도 Debug scenario DB**에만 합성 입력하고 화면에 개발용이라고 표시한다. 한 플랫폼의 가짜 좌표를 다른 플랫폼의 실측 성과로 표현하지 않는다.

지도 SDK/TDS 복제품 대신 기존 디자인 모듈과 Compose Canvas의 좌표 이동선을 쓴다. 지도 타일·호환되지 않는 TDS 자산/코드의 도입 시간을 아끼고 기록 정확성·양 플랫폼 저장/복원에 시간을 배정한다. 지도 타일이 없음을 UI와 README에 표시한다. 사용자 피드백으로 원본 앱의 화면 구조가 핵심임을 확인해 [ADR-011](011-original-ui-fidelity.md)에서 원본 고정 샘플 지도 자산과 기존 색상·정보 순서를 재구성하기로 했다. 샘플 지도는 실제 위치와 무관함을 UI에서 명시한다. 네이티브 권한·앱 수명은 플랫폼 host가, 사용자별 저장 규칙은 공통 domain/data가 맡는다. 위치 callback은 산책 ID·재개 segment와 묶고 늦은 callback은 Room transaction에서 버린다. 산책이 진행 중이더라도 앱이 배경으로 가면 중단 처리하며, background tracking 성능은 주장하지 않는다.

기존 기능별 모듈 경계와 Koin/생성자 주입을 유지한다. `feature:dogs`와 `feature:history`는 화면만, `domain`은 계약/거리, `data`는 Room migration과 원자적 기록, Android/iOS host는 권한·lifecycle을 담당한다. 얇은 UI 모듈을 위한 형식적 단위 테스트는 추가하지 않고 두 플랫폼 컴파일과 실제 UI 테스트로 확인한다.

독립 리뷰 후 보강: 앱이 `start`/`resume` 저장 직후 배경으로 전환될 때 Room Flow의 화면 상태가 늦게 갱신될 수 있다. 사용자 범위 런타임은 배경 전환 시각을 보존하고 해당 시각 이전에 시작한 Recording이 나중에 나타나도 그 시각으로 중단한다. 중단 대기 중인 구간에는 체크포인트를 더하지 않는다. Room v4는 타이머 체크포인트와 구간 시작 시각을 별도 칼럼으로 저장하여, 체크포인트 전후를 막론하고 구간 시작 전 GPS callback을 거절한다. v3의 시작 시각을 복원할 수 없는 기록은 마지막 체크포인트를 보수적인 경계로 사용한다.

## 재검토 조건과 검증

전체 100점 범위로 복귀하면 M04 서명·TestFlight·실기기 결과를 먼저 채우고 M06 실제 인증/UID 전환, M07 완전한 반려견 관리, M09/M10 각 플랫폼 위치/지도/배경 정책, M11 동기화 및 나머지 티켓을 진행한다. 이 시연의 로컬 UID를 Firebase UID로 승격하지 않는다. 공개 README는 실제 검증한 명령·기기·결과와 미검증 범위를 분리한다.

이 결정의 성공 조건은 JVM+iOS KMP 테스트, Android Activity/Compose 실제 실행, iOS Swift UI 실제 실행, 기존 v1/v2 Room 보존, Debug 합성 경로의 Release 배제, 현재 코드의 CI와 독립 리뷰다. Signed APK·TestFlight·물리 기기 결과가 없으면 배포 완료로 판정하지 않는다.

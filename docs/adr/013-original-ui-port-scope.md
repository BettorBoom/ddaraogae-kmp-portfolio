# ADR-013 · 원본 화면 전체 이식의 범위와 정직한 경계

- 결정일: 2026-10-10
- 결정자: 사용자(원본과 같은 수준의 UI/UX를 Android·iOS에서 확인, 기술 선택은 위임), Claude(위임 범위 안의 세부 결정)
- 상태: 채택하고 2026-10-11에 구현했다(착수 전에 먼저 제안·기록했다). 구현·검증 결과와 달라진 점은 [제출 devlog](../devlogs/M10.md)와 [화면별 패리티 표](../ui-parity.md)에 갱신한다.
- 관련: [ADR-011](011-original-ui-fidelity.md)(색·정보 순서 보존), [ADR-010](010-deadline-local-core.md)(로컬 핵심 범위), ADR-008(인증 착수 정책: 클라우드·서명 등 전달 준비의 전체 검증 전에는 제품 로그인을 시작하지 않는다)

## 문제와 근거

ADR-011 이후에도 사용자는 시뮬레이터 화면이 원본과 다르다고 지적했다. 홈의 큰 설명문, Material 타이포, 단순 그래프, 이름 편집 행은 원본(`fragment_home.xml` 32sp 제목·20dp 여백·8dp 카드)과 달랐고, 산책 모아보기·도장·마이페이지 하위·로그인은 아예 없었다. 원본의 도장 규칙(`FirebaseDataSourceImpl.checkStampCondition`)·홈 문구 규칙(`HomeFragment`)·표기 규칙(`TextConverter`)은 서버 없이 로컬 산책 이력만으로 계산할 수 있다는 것을 소스에서 확인했다.

## 결정

1. **기준 우선순위**: 복제 대상은 원본 저장소 HEAD의 XML·strings·dimens·Kotlin 로직이다. README 스크린샷(2024-07)과 다르면 HEAD를 따르고 차이를 `docs/ui-parity.md`에 적는다. 소스의 오타 "흭득"은 "획득"으로 고친다.
2. **로컬 이력에서 계산**: 도장 8종, 주간 달성률, 일별/월별 거리, "N 시간 전" 문구는 저장하지 않고 `domain` 순수 함수로 이력에서 매번 계산한다(멱등). 시간대 계산에 `kotlinx-datetime` 0.7.1을 `domain`에 명시한다. 이미 전이 의존성으로 Gradle 캐시에 있어 새 다운로드가 없다.
3. **데이터 변경은 가산적 1건**: Room v4→v5로 `dogs`에 `gender/age/breed/memo`(전부 nullable)를 추가해 반려견 폼과 목록의 성별 표시를 실제로 저장한다. 반려견은 **1마리**를 유지하고(여러 마리·사진은 미구현) "추가하기"는 1마리 안내를 보여 준다. 기존 v4 행의 성별은 추정하지 않고 NULL로 둔다. 실패하면 이 변경만 되돌리고 폼을 이름만 저장하는 상태로 표시한다.
4. **지도**: 원본 샘플 이미지 + 저장 좌표의 상대 이동선을 유지하고 연결 지점은 `MapBackdrop`/`RouteMap` 한 곳으로 모은다. 실제 지도 SDK(Android Naver Map, iOS MapKit)는 후속이다.
5. **로그인/회원가입**: `feature:auth`에 UI만 옮기고 시나리오 갤러리에서만 보인다. 제품 흐름에는 넣지 않는다(전달 준비 전체 검증 전에는 제품 로그인을 시작하지 않는 정책 유지). 로그아웃·회원탈퇴·약관·개인정보처리방침·알림 예약은 "연결 전" 안내를 보여 준다. 약관·방침 본문은 원본 팀의 법적 문서이므로 복제하지 않는다.
6. **산책 규칙 차이**: 원본은 위치 표본이 2개 미만이면 저장하지 않지만 이 앱은 검증된 "시간만 기록" 동작을 유지한다. 산책은 이미 Room에 저장되므로 원본 완료 화면 뒤로가기의 "저장되지 않습니다" 다이얼로그는 만들지 않는다. 중단/재개는 원본에 없어 산책 화면에 원본 스타일의 추가 시트로 제공한다.
7. **글꼴·다크**: SF Pro는 재배포 조건과 한글 글리프 부재(원본도 한글은 시스템 폰트) 때문에 넣지 않고 시스템 글꼴을 쓴다. 다크 모드는 원본 `values-night` 값을 따르되 `ContrastTest`가 통과해야 한다.
8. **알림 리마인더**: 목록·빈 상태·추가 버튼 UI만 두고 예약하지 않는다. 가짜 항목을 만들지 않고 연결 전임을 밝힌다.

## 대안과 포기하는 것

- 이름만 저장하는 폼 유지: 위험은 낮지만 첫 실행 경로의 폼이 원본과 달라 사용자 지적이 반복된다.
- 여러 마리 지원: 산책 테이블이 반려견 ID 대신 이름 스냅샷만 가져 별도 마이그레이션·선택 UI·테스트가 필요하다. 오늘 범위를 넘어 후속으로 남긴다.
- SF Pro 동봉: 시각은 가까워지지만 라이선스 위험이 있고 한글에는 효과가 없다.

## 재검토 조건

실제 지도 SDK를 도입하거나 인증 착수 조건(전달 준비 전체 검증)이 충족되거나, 여러 마리 요구가 생기거나, Room v5 마이그레이션 테스트가 실패하면 이 결정을 다시 연다. 검증 결과와 남은 차이는 devlog와 `docs/ui-parity.md`, `docs/migration-gap-audit.md`가 현재 사실이다.
